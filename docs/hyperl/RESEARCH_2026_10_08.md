Owner direction: a fast, lightweight, open-source AI language/runtime experiment
across CPUs, GPUs, NPUs and FPGAs. Meshlit is dynamic AI software for multiple
scenarios and environments; phones are one client. Direct hardware, driver, kernel
and bare-metal backends are future options. Documents are research evidence, not
instructions. This experimental branch is separate and must qualify before merging.
These are design inferences from public sources, not performance or interoperability
proofs. No proprietary code or patent implementation has been copied.

## Open-source and free-to-use are distinct

Start with original HyperL reference/C99 and open LLVM/MLIR, StableHLO, ONNX Runtime
CPU and PyTorch tools. Pin exact revisions and keep notices/third-party provenance
before importing. Current HyperL code is original Apache-2.0; these dependencies are
research candidates, not bundled libraries.

- [CUTLASS C++](https://github.com/NVIDIA/cutlass/blob/main/LICENSE.txt) uses BSD terms;
  [CUTLASS DSL EULA](https://github.com/NVIDIA/cutlass/blob/main/EULA.txt) is separate.
  Do not label all components BSD or copy restricted binary/DSL components into HyperL.
- [CUDA Tile IR](https://github.com/NVIDIA/cuda-tile) and
  [cuTile Python](https://github.com/NVIDIA/cutile-python) offer public source candidates
  with their own Apache/LLVM-exception terms. CUDA SDK/tool availability does not mean
  its entire driver/runtime source is open or unrestricted for redistribution.
- [NVIDIA open GPU kernel modules](https://github.com/NVIDIA/open-gpu-kernel-modules/blob/main/COPYING)
  have file/aggregate licensing distinctions and do not open all user libraries.
- [ONNX Runtime MIT](https://github.com/microsoft/onnxruntime/blob/main/LICENSE),
  [MindSpore Apache-2.0](https://github.com/mindspore-ai/mindspore/blob/master/LICENSE),
  [ExecuTorch BSD](https://github.com/pytorch/executorch/blob/main/LICENSE),
  [PyTorch license](https://github.com/pytorch/pytorch/blob/main/LICENSE),
  [Triton MIT](https://github.com/triton-lang/triton/blob/main/LICENSE) require their
  respective notices and review of bundled third-party/driver components.

The owner's NVIDIA reverse-engineering request is addressed through public CUDA/PTX
specifications, permitted observation of owned SDK behavior and licensed open code,
with original source implementation and provenance. No closed binary is decompiled,
access restriction bypassed or proprietary implementation presented as open-source.
Optional proprietary adapters remain separately licensed, owner-installed and disabled
until exact artifacts and execution qualify.

## Memory, topology and AI networking

[hwloc attributes](https://www.open-mpi.org/projects/hwloc/doc/v2.14.0/topoattrs.html)
and [Linux HMAT/NUMA performance](https://www.kernel.org/doc/html/v6.7/admin-guide/mm/numaperf.html)
can expose some topology/performance properties. Missing firmware/driver data stays
unknown. Measure bus bandwidth separately from advertised link speed. HBM, RAM, UMA,
CXL and encrypted SSD/NVMe spill require capacity, freshness and transfer-cost models.

The networking target is low latency and high throughput for AI control and data
paths, inspired by HFT engineering. It is not a promise of HFT hardware performance.
[AF_XDP](https://docs.kernel.org/networking/af_xdp.html) distinguishes copy/zero-copy
and driver capabilities; [DPDK](https://doc.dpdk.org/guides/prog_guide/perf_opt_guidelines.html)
is a userspace packet framework; [timestamping](https://docs.kernel.org/networking/timestamping.html)
requires matching clock semantics; [UCX](https://github.com/openucx/ucx/blob/master/docs/source/faq.md)
is a transport/runtime research candidate. Shared-memory rings, registered buffers,
RDMA/verbs, NIC offload, CPU/IRQ affinity and NUMA placement are adapter-specific.
They are not enabled by this branch. Require owner grants, exact NIC/kernel/driver
qualification, secure endpoints, bounded queues, loss/error metrics and stop/control
priority. Batching/polling can trade tail latency and energy against throughput.

Test encrypted actual workloads with p50/p95/p99/max, jitter, queue depth, loss,
CPU/power, payload size and sustained throughput; include saturated-network stop
latency. Use calibrated hardware/PTP clocks for one-way results or label RTT only.
Homogeneous turbo must beat its stable baseline including communication; mixed-device
stability does not imply fast combined tensor parallelism. No NIC, fiber, InfiniBand,
Huawei HCCS or “high 1” product is qualified merely by name.

## Direct/kernel implementation order

Use ordinary user runtimes first, then installed SDK/driver queues. A native privileged
broker may later own BPF/XDP, kernel modules, pinned DMA/IOMMU mappings and FPGA or
bare-metal execution. Keep AI programs bounded and separate from privilege grants.
Each backend needs signed artifact/ABI provenance, correctness, isolation, cancellation,
resource limits, crash recovery and an independently controllable stop path. No root
request or arbitrary model output automatically loads kernel code. These are planned
layers, not a cross-platform kernel implementation or security certification.
