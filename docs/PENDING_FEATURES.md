Updated 2026-10-23. This is a current delivery checklist, not a claim that a visible menu implements its backend. Detailed Android and Studio evidence lives in [PROGRESS](../PROGRESS.md), [TODO](../TODO.md), and the [Desktop feature tracker](DESKTOP_FEATURE_TRACKER.md).

## First: prove the device experience

- Qualify the current QR scan, save, verify, connect, reject, renewal notification and pairing history on Samsung and Xiaomi. Retest failed and concurrent requests, expiration, revocation, owner offline, IPv4 and IPv6 endpoints, and live status without leaving the screen.
- Finish screen-by-screen Android layout review on both phones, including larger fonts, landscape, light and dark palettes, long names/IDs and dialogs. Build/lint success alone does not prove every screen fits.
- Make local device discovery and device category identification reliable across Wi-Fi, BLE and IPv6; general LAN inventory is separate from Meshlit peer advertisements and is not implemented.
- After mutual pairing approval, exchange fresh authenticated capability and load offers on both phones, then add an owner-controlled Auto / On / Off policy for using approved peer resources. Automatic discovery currently defaults on while the app is visible, but it does not automatically choose a peer for model work or grant access to its sensors, tools or device controls.
- Add an Ansible-like Meshlit fleet configuration plan: select approved devices and typed settings, preview each device's change, bind the approved plan hash and permissions, apply with per-device status, record partial failures and offer a separately reviewed recovery plan. Existing host-side Ansible design and pinned SSH are not an implemented Meshlit fleet controller; agents need their own scoped delegation and cannot silently apply scripts to the whole cluster.
- Validate Radar's live-only indexed dots, pulse, direct identity review, device table, identifier toggle and animation on both phones. Saved endpoints now stay in a separate list. Unknown direction/range is displayed explicitly; true relative placement still needs permissioned ranging or shared positions plus local heading, and must be tested on hardware. Samsung rendered the offline Natural Earth map and opt-in OpenStreetMap tile layer. The map also has local-only current-position centering and an optional IMON HTTPS public-IP lookup; its server URL and a public IP must be supplied by the user, so no remote lookup has been accepted yet. The global host map uses owner-set approximate coordinates shared only inside one joined or hosted relay; it is not a public worldwide directory, GPS tracker or verified proof of origin. Add consented cross-relay directory federation and stronger host status reporting before claiming global search.
- Demonstrate two independent phones executing one model across actual layers, including oversized weights, throughput, worker loss and safe retry. Saved devices and job forwarding are not this proof.
- Build monetary-grade metering and privacy-gated reward proofs. The local wallet opt-in, durable self-signed receipt totals and live process counters are now visible in Contribution measurements, but energy, bytes, requester confirmation and cross-signed proof sharing are absent. Do not spend, rent, exchange, publish raw logs or auto-enroll participants from these local credits.

## Android product gaps

- Finish durable multi-device mesh conversations: participants, rooms, message sync, offline queue, history, delivery receipts and safe device removal. Current peer chat is narrower.
- Complete remote relay/reverse tunnel and automatic transport negotiation across LAN, VPN and Internet; test NAT/firewall behavior and mixed local/remote clusters. The built-in relay does not yet carry native layer RPC.
- Qualify non-Meshlit interoperability on real LAN, VPN and public HTTPS services. Manual URL enrollment records an HTTP response and a user-labeled device category only; actual work requires a separately approved MCP, model API or SSH adapter. The authenticated Web/API bridge lets a browser request typed Meshlit commands with owner-approved scopes and a seven-day credential expiry, but browser enrollment, expiry, revocation and task denial still need device tests. No generic webpage becomes a compute worker by being reachable.
- Add confirmed inbound IPv6 hosting, advertisement and firewall coverage. Manual/QR endpoint formatting can accept IPv6 URLs, but the current inference listener binds IPv4 by default.
- Add robust QR lifecycle: permanent versus expiring codes, image save/share/delete, rotation and invalidation, camera/live/gallery tests, and clear pending-request queue controls.
- Complete compatible model catalog, hardware admission, verified download/import/load quality checks, routing and meaningful local/remote model choices on both phones. Distinguish sequential routing from layer sharding.
- Evaluate NVIDIA Nemotron 3 Nano 4B as an optional Studio/server and high-memory-phone model; its official Q4 GGUF is 2.84 GB and hybrid architecture is not yet admitted by the Meshlit layer planner. Compare NVIDIA, AMD, Apple and CPU worker backends with measured, pinned runtimes; see [Nemotron and mixed-hardware research](NEMOTRON_AND_HETEROGENEOUS_SHARDING_2026-10-23.md). Port HyperL's bounded CPU graph to server/container, then implement tested GPU/NPU/TPU adapters and a typed cross-device graph scheduler before claiming simultaneous mixed-architecture compute.
- Add an admitted resident multi-model pool only after the phone runtime can hold independently addressable sessions: check free RAM, KV/workspace per model, storage, battery and thermal limits; expose each load/unload state in Models and Chat; route by explicit scenario and observable capability; fall back to sequential swapping only when the owner permits it. Today one local model is active at a time, although a route can use up to three installed/online steps sequentially.
- Evaluate [Laya](https://github.com/receptron/laya) as an optional Studio/server decision model for typed routing, resource admission and risk signals. Its Node.js/ONNX package and roughly 1.7 GB model weights are unsuitable for bundling in the Android APK. A host adapter needs pinned weights, measured latency and accuracy, authenticated requests and explicit human approval for pairing, payments and security changes; a separate on-demand Android ONNX port would need hardware admission. Laya is not a chat or speech model.
- Finish agent/MCP/hook authority and real parallel execution acceptance: per-tool scopes, expiry, revocation during work, approval for sensitive actions, durable audit and recovery. Background control remains bounded by Android permissions and owner choices.
- Qualify the built-in, hostless phone agent with a genuinely tool-capable on-device model and physical Chrome task tests. Its native loop and saved app scope are wired, but the bundled 0.5B model failed simple tool-choice trials on Mac; eight-action bounds do not establish autonomous task success. Keep optional external agent frameworks behind reviewed adapters; see [built-in agent design](BUILT_IN_AGENT_DESIGN.md).
- Qualify the new Agent registry/logs and host-only MCP catalog on device. Add an owner-reviewed permission wizard, server health and expiry; installed Filesystem/Fetch/Memory/GitHub/Playwright hosts remain external. Verify the whole-app emergency stop revokes phone automation and closes the background node and gateway, while remote work is separately reconciled.
- Expand user-selected RAG sources, connectors, visual input, live camera and voice with tested permissions, provenance and privacy indicators. Training/fine-tuning needs a compatible external runtime; Android autograd training is not implemented.
- Add durable inline image/file chat messages, local VLM ingestion and reviewed PDF/office parsers. Current Chat photo picker can submit a selected image to an explicit online vision provider and put only its description into the editable draft; original pixels are not stored in the conversation.
- Qualify online speech with an actual enabled OpenAI-format account and model IDs: provider selection, network-audio consent, WAV transcription, synthesis, playback, cancellation and billed usage. The picker now blocks missing setup, but a successful account-backed voice turn has not been observed.
- Turn the visible RAG mode control into real durable local/remote retrieval with source attribution; the older in-memory store and placeholder endpoint are not sufficient.
- Qualify battery, thermal, resource and CPU charts under real load, power policy, diagnostics and repair/rollback, plus accessibility and settings persistence across upgrades.
- Build app-wide energy/cost attribution for local models, downloads, agents, peers and cloud calls. Current battery-side discharge is whole-device and sampled only while Power & costs is open; provider billing is separate. Let authenticated Internet devices opt in to live load/health/uptime sharing with source, freshness and per-metric privacy controls.
- Expand the Hugging Face account dashboard beyond verified token access, GGUF discovery and hosted text requests: gated entitlement acceptance, actual billing/usage and more hosted tasks require provider APIs and account tests. Keep public discovery separate from authenticated or paid use.

## Studio, server and container gaps

- Port Android device discovery, QR/trust management, groups, mesh chat, layer-worker enrollment, native RPC controller and dashboard with independent desktop/server tests.
- Finish agent/MCP/A2A/hooks, durable permission controller, credential vault, audit, autonomy stop/revoke, RAG/memory/voice and cloud adapters. Current menus are not equivalent to these backends.
- Finish model download resume and entitlement checks, native Ollama/LM Studio lifecycle, full terminal/SSH workflows, clean package installation and longer running stability tests.
- Add verified read adapters for selected additional cloud providers, preserving currency, billing period, source and partial results. Implement Terraform/Pulumi through an owner-supplied host runtime: inspected plan, exact workspace/account binding, explicit human approval for apply/destroy, and logged outcome with rollback guidance. No local CLI or executable is bundled in the current Android or Studio build.
- Add qualified container/VM/Kubernetes control, firewall, resource/power metering, recovery/failover and replicated task/KV journals. Linux, Windows and Apple Silicon packages require their own runtime checks.

## Rewards and release gates

- Move from local activity credits to measured service units, reciprocal receipts, offline reconciliation, replay/collusion checks and dispute handling before balances can represent monetary value.
- Complete payment/legal/processor work before purchases, rental, exchange or payouts.
- Production signing, privacy/dependency checks, clean-target install, physical fleet tests and release artifact verification remain open. Experimental debug builds must be labelled accordingly.
