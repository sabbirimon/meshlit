## Acceptance sequence

1. Complete local desktop foundation: actual packaged offline generation/load/unload, monitor sampling, model import/download cancellation, terminal exit/cancellation, SSH pins and HyperL native recipes.
2. Port permission/credential/audit controllers before exposing full-auto agents, hooks and MCP; validate revocation during a running action and deny after expiry or wrong scope.
3. Add VM/container/kubernetes adapters with real installed runtimes, workload limits and tested lifecycle. Keep OS elevation a visible authenticated human action.
4. Qualify network/device/cluster paths: Mac plus Samsung first, then owner’s old Windows PC and Xiaomi by model/OS/connection. Distinguish independent devices from same-host fixtures.
5. Add remaining voice, Dolphin ASR, RAG, cloud billing, browser/PC control and recovery adapters; retain unknown values and missing credentials/runtime states.
6. Release Experimental packages with evidence. Admit only qualified capabilities to a separate Core production candidate; a source build is not “production grade”.

## Agent, hook and MCP coverage requirement

Every feature intended for automation must have a shared controller and a typed tool adapter;
human UI, hooks, MCP and agents call that controller with their own authority. An approved
full-auto session may continue within scopes and budgets until completion, expiry, revocation
or Stop. Authentication, trust, credential edits and OS permission dialogs do not disappear.
Desktop PC/browser control is a separate powerful scope; encrypted local retention and audit
must precede persistent autonomous jobs. The current human terminal panel is not yet that bridge.

## Build record rule

For each update record source revision, feature IDs changed, passed and failed commands,
actual runtime/device evidence, known limitations, package hashes and release URL in the
[build log](DESKTOP_BUILD_LOG.md). Append corrections; do not turn historical tests into new-build proof.

## Source continuation — 2026-10-24

Knowledge library now uses shared bounded text retrieval, an AES-GCM passphrase-unlocked local vault, import/search/remove and separate local/remote chat grants. Model recommendations now use the shared revision/hash catalog with observed host capacity and the existing verified download client. HyperL gains bounded repeated native measurements, a ten-second deadline and capped result previews; revocation waits for cancellation before admitting another operation. These source additions are not in the published build40.1 installer. Final desktop tests/render checks and native measurements remain qualification gates; broader daemon/MCP/agent/cluster parity remains open.
