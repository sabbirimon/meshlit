## Agent-to-agent conversation increment

The owner requests bidirectional delegation on both Android and Studio. The new `AGENT_DIALOGUE` team control reuses the existing selected roles, approved sources, durable jobs and encrypted run history. A selected member can issue a strict `delegate` decision to another member, receive its correlated reply and continue; return requests such as A → B → A share the same call/depth budget. The coordinator assigns authors and message IDs. Model output cannot add participants or enlarge permissions. Pause, Stop, per-call revocation, restart interruption and the ten-minute team deadline remain in force. Conversation mode allows at most `maxRounds × 4` model calls and three nested delegations; exhausting either limit reports `LIMIT_REACHED` rather than completion.

Android also lists enabled, agent-approved compatible model profiles as explicit team targets, so a phone can use an approved desktop model endpoint. Target IDs bind the public endpoint/model profile snapshot; edits invalidate an older selection. Studio already uses approved compatible routes for remote members. Typed Android peers use explicit `promptFormat=INSTRUCT` for this new mode so the receiver applies its own model template; legacy raw-completion requests retain `RAW` by default. Remote listeners, credentials and team delegation are never enabled automatically. These are model-task messages; other device actions retain their separate grants.

`AgentDialogueCoordinatorTest` covers reverse requests, attributed/correlated replies, unknown targets and forged fields, limits, cancellation and revocation. Desktop persistence and Android provider-target binding have additional regressions. The opt-in `AgentDialogueDeviceTest` requires real model output, an actual routed task and matching reply; a valid JSON response or zero-call refusal is not live proof. The latest actual-task-example build passed core-mcp (185 tests), desktop-device (29), desktopApp (88, one fixture skip), both latest app suites (326 each), both APK builds, the V2 test APK and desktop distribution creation. Both final Android lints passed with zero errors. Physical scope and remaining gates are recorded below.

The initial lead must send a real peer task before the run can complete. Premature direct replies consume the existing bounded call budget. Mandatory handoff prompts show only the delegate decision and include the real assigned task as their example: the small models copied generic example text in failed trials. Strict JSON parsing and target/field checks remain after generation. A routed reply is evidence of communication, not evidence that its answer or workflow is correct.

## Connection assistance increment — November 3

Both Android flavors and Studio now contain default-off connection assistance. In Android Chat, select Device connection assistance in tool choices, then ask `list saved devices`, `connect Samsung` (using the exact saved name), or `show connection status`. Studio supports the same explicit commands without loading a model; its tool-enabled modes also expose the bounded `device_connection` tool. Actual source choices appear in Chat. Owner settings separately approve the exact saved configuration before contact; changed endpoints, pins, model IDs or action scopes invalidate approval.

Android adapters check pinned SSH STATUS, already-paired HTTPS device status, or a saved model API catalog under their existing agent scopes. Studio checks saved compatible model APIs. MCP executable configurations, unverified nearby advertisements and Studio address-only records are setup-only. No arbitrary address is contacted from a Chat message. Contact checks do not automatically switch a chat model, enroll native workers, grant other commands or share memory continuously. A public model catalog is not account-authentication proof.

Each check has at most two ten-second read-only attempts, cancellation and revocation monitoring, actor-bound two-minute choices, persisted terminal receipts, and restart interruption without replay. Studio metadata/receipts use a purpose-bound encrypted vault document; credentials are read from SecretStorage only after fresh source approval and stay transient in private IPC. Android uses its existing encrypted source stores. Policy setters are absent from model tools. Delegated Android clicks/text entry in Meshlit's own app are now refused so all-app accessibility cannot self-grant permissions; ordinary human input remains available. Studio already excludes its own bundle in both its policy and native app-access helper.

The coordinator's nine new tests cover changed identities, foreign/expired offers, cancellation, revocation, retry limits, setup-only sources, storage failure and restart interruption on Android and desktop JVMs. Additional parser, private bridge, vault and catalog transport regressions cover the platform adapters. These checks do not qualify the newly added connection workflow on a physical phone or prove Wi-Fi/4G seamless task recovery. See the [real mixed WAN native execution record](desktop/evidence/mixed-mac-samsung-wan-native-20261103.json) for the separate Mac/Samsung inference and controlled-disconnect proof.

## Draft autosave regression — November 3

Typing again during an in-flight draft save cancels its prior coroutine. The old broad failure handler treated that normal cancellation as a storage error. The fix rethrows cancellation, retains genuine write-failure warnings, and clears only the draft warning after a successful retry. Both Android flavors passed the two focused cancellation/failure regressions in `ChatDraftPersistenceTest` (52-second Gradle check). [Regression evidence](desktop/evidence/draft-save-regression-20261103.json) separates tested source from the final installation handoff.
